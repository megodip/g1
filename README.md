# Vegas — мини-портал для кнопочных телефонов

Веб-портал, который работает в браузере **без JavaScript** — на любом кнопочном
телефоне с WAP/HTML-браузером (Opera Mini, стандартные браузеры, WML-режим).

Вкладки: **Поиск · Загрузки · Библиотека · Флибуста · Чат · Архив · Вега**
(Вега — ИИ-агент с доступом к серверу).

## Запуск

```bash
python3 server.py          # http://IP_СЕРВЕРА:8000
```

Зависимостей нет — только Python 3.7+. Данные создаются в `data/` автоматически.

Настройки — в `app/config.py`, всё можно переопределить переменными окружения:

```bash
VEGAS_PORT=8080 python3 server.py          # другой порт
VEGAS_LLM_KEY=sk_... python3 server.py     # ключ модели для Веги
```

## Как открывать с телефона

Находишься в одной сети с сервером → открываешь `http://IP_СЕРВЕРА:8000`.
Шапка чёрная, навигация пронумерована (1–7) и поддерживает accesskey:
в Opera Mini быстрый переход — `#` + цифра (на некоторых моделях `*` + цифра).

## Книги: Библиотека + Флибуста

- **Библиотека** (`/library`) — книги, сохранённые на сервере чистым текстом.
  Поиск по названию и автору, чтение постранично (текст режется по абзацам,
  страница ~6 тыс. знаков), удаление. Хранение: `data/library/<id>.txt` +
  карточки в `data/library.json`.
- **Флибуста** (`/flibusta`) — поиск по сайту (OPDS + HTML-фолбэк). Форматов
  (epub/pdf/...) нет намеренно — кнопочный телефон их не читает. Вместо этого
  у каждой книги кнопка **«в библиотеку»**: сервер скачивает fb2, вытаскивает
  из XML-структуры только автор/название/абзацы (сайт-мусор в текст попасть
  не может; fb2 бывает за-zip-ован — распаковывается) и сохраняет книгу
  в Библиотеку. Запасной вариант — plain txt. Повторное сохранение не
  дублирует книгу, а открывает уже сохранённую.

## Механика чата (почему ввод не ломается)

Раньше страница чата перезагружалась целиком каждые 7 секунд, сбрасывая ввод.
Теперь (как в wapchat):

```
/chat          рамка с полем ввода — НИКОГДА не перезагружается сама
/chat/frame    сообщения внутри <iframe>; у НЕЁ стоит <meta refresh 6с>
/chat/send     форма отправляет с target="chat_frame" — ответ уходит в iframe
```

Перезагружается только область сообщений. **Новые сообщения показываются
сверху** — только что отправленное видно сразу, без прокрутки. Для телефонов
без iframe есть `/chat/simple` — полная страница с ручным обновлением.
Ник передаётся и в куке, и в URL (`?nick=...`) — работает даже если браузер
не хранит куки.

## Структура проекта

```
server.py            точка входа
app/
  config.py          ВСЕ настройки (порты, лимиты, LLM, зеркала Flibusta, вкладки)
  core/              HTTP-ядро: запрос/ответ, роутер, сервер
    http.py          Request (query, куки, форма) и Response (html/redirect/file)
    router.py        таблица маршрутов "метод + путь -> обработчик"
    server.py        диспетчер запросов и отправка ответов
  ui/                оформление
    layout.py        каркас страницы, CSS (чёрная шапка), навигация
    components.py    готовые блоки: сообщения чата, пагинация, ошибки
  services/          бизнес-логика без HTML
    fetcher.py       серверный HTTP-клиент + расшифровка кодировок
    storage.py       папки данных, имена файлов, история чата (JSONL)
    library.py       локальная библиотека: карточки + тексты книг
    llm.py           клиент LLM (OpenAI-совместимый / Ollama) + запуск shell
  modules/           вкладки портала (каждая — самостоятельный файл с ROUTES)
    search.py        Google -> DuckDuckGo, редирект "/"
    reader.py        прокси-читалка чужих страниц + прокси картинок
    downloads.py     файлы: список, закачка с телефона, раздача
    library.py       локальная библиотека: список/поиск/постраничное чтение
    flibusta.py      поиск по Flibusta + сохранение чистого текста в библиотеку
    chat.py          чат (iframe-механика выше, новые сообщения сверху)
    archive.py       текстовые заметки
    vega.py          ИИ-агент с shell-доступом
```

## Вега — ИИ-агент

Вега общается с LLM и может выполнять shell-команды на сервере (метка `@@RUN`
в ответе модели). По умолчанию команда требует подтверждения кнопкой.
Модель настраивается в `app/config.py` (`LLM_STYLE` = `openai` для любого
OpenAI-совместимого API или `ollama` для локальной Ollama).

**Внимание:** если ключ LLM когда-либо попадал в публичный репозиторий —
считай его скомпрометированным, перевыпусти и передавай через `VEGAS_LLM_KEY`.

## Разработка

Перед правками прочитай **AGENTS.md** — там правила UI для кнопочных телефонов,
карта модулей и пошаговый рецепт добавления новой вкладки.

Тестирование после изменений: `bash scripts/test_vegas.sh` (нужен запущенный
сервер на :8000) — проверяет все маршруты, чат-механику, библиотеку и
отсутствие JS.
